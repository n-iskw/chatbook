# Mac音声でPDFページを読む

chatbookで現在表示しているPDFページを、macOSの「Speak selection」と同じ音声で読み上げます。
ページ本文を画面外の専用テキスト領域で選択し、macOSの `Option + Esc` を実行する方式です。
PDFの可視テキストレイヤーや、選択して質問するためのUIは変更しません。
そのため、`AVSpeechSynthesizer` やブラウザの `SpeechSynthesis` ではなく、macOSの「読み上げコンテンツ」
で設定した声（Siri / Neural音声を含む）を使えます。

## macOSの初回設定

### Read & Speak（読み上げコンテンツ）

「システム設定 > アクセシビリティ > 読み上げコンテンツ」で次を設定します。

- 「選択項目を読み上げ」をオン
- システム音声: `Siri (Voice 2)`
- システム音声言語: 「日本語」
- 「言語を自動検出」: オフ
- 「Pronunciations」: オン

`Option + Esc` はmacOSの「選択項目を読み上げ」に割り当てられたショートカットです。
別アプリでテキストを選択して `Option + Esc` を押し、期待する音声になることを先に確認できます。

### アクセシビリティ権限

「システム設定 > プライバシーとセキュリティ > アクセシビリティ」で、
`npm run speech:bridge` を実行するアプリを許可します。通常は次のいずれかです。

- macOSのTerminal.app
- iTerm2
- VS Codeの統合ターミナルから起動する場合はVisual Studio Code

Chromeはキーイベントの送信元ではないため、この権限をChromeに与える必要はありません。
権限を追加・変更した後は、ターミナルと音声ブリッジを再起動してください。

## 起動

chatbookのローカル開発サーバーとは別のターミナルで、リポジトリのルートから起動します。

```bash
npm run speech:bridge
```

pnpmを使っている場合は `pnpm run speech:bridge` でも起動できます。

既定では `127.0.0.1:8789` だけで待ち受け、chatbookの標準ポートである
`5173` と、現在の開発環境で使っている `5174` のローカルOriginだけを許可します。
ポートを変えた場合は、許可するOriginを環境変数で指定できます。

```bash
MAC_SPEECH_ALLOWED_ORIGINS=http://localhost:5180 npm run speech:bridge
```

## 使い方

1. Mac音声ブリッジを起動する
2. chatbookを `http://localhost:5174` で開く
3. PDFの表示領域右上にある「このページを読む」を押す
4. ページを移動すると、前のページの読み上げは停止する

macOSのSpeak selectionは、chatbookから再生中の一時停止・速度変更イベントを受け取れません。
そのため、この経路では再生中のボタンが停止操作になります。速度はmacOSの読み上げ設定で調整してください。

## 仕組みと制約

- 現在ページの本文を画面外の専用テキスト領域へ設定し、その領域だけを選択します（PDFの可視テキストレイヤーは選択しません）
- ローカルHTTPブリッジがSwiftヘルパーへ「Speak selection」の開始・停止を渡します
- Swiftヘルパーがアクセシビリティ用のキーイベントとして `Option + Esc` をmacOSへ送ります
- APIキーや外部の音声サービスは使いません
- 初回は、ブリッジを起動したターミナル（または統合ターミナルの親アプリ）にmacOSのアクセシビリティ権限が必要です
- Mac以外やブリッジ停止中、PDFテキストレイヤーがまだ描画されていない場合は、ブラウザ標準の読み上げへフォールバックします
- 音声はブリッジを起動したMacから出力されます。iPadなど別端末のスピーカーからは出ません

Macの音声を変える場合は、macOSの「システム設定 > アクセシビリティ > 読み上げコンテンツ」で
「システム音声」を変更してください。「言語を自動検出」は、英単語だけ別の声に切り替わるのを避けるため
オフにし、必要なら「Pronunciations」を有効にします。Safariリーダーの内部読み上げAPIを呼び出す方式ではありません。
